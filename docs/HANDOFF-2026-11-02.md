## 4. 环境坑（本机 Windows 实测，全部踩过）

1. **gh/git 凭据分离**：环境变量 `GITHUB_TOKEN`（fine-grained PAT）对 issue API 与 push 均 403——
   读写一律 `env -u GITHUB_TOKEN` 走 keyring classic token；push 配方
   `env -u GITHUB_TOKEN git -c credential.helper='!gh auth git-credential' push origin <branch>`；
   网络不通时前置 `https_proxy=http://127.0.0.1:10808`（crates.io API 查询同样需代理）
2. **切分支先对基线**：本地 `main` 引用可能落后 origin/main——开新分支前先
   `git fetch origin main && git merge --ff-only origin/main`，再 `checkout -b`；
   本会话两次因"从旧 HEAD 切分支"返工（一次整个 PR 基线错误重做）
3. **windows crate 0.62 的 async 类型在 `windows-future` crate**：依赖版本必须与
   windows 0.62.2 对齐（**0.3.2**——lockfile 出现 0.2.1/0.3.2 两份实例会导致 trait bound 分裂）；
   0.3 把阻塞等待从 `.get()` 改名 **`.join()`**
4. **`snapshot_window` 的 rect 是屏幕物理像素**（UIA `CurrentBoundingRectangle`）——
   归一化直接除屏幕尺寸，**不加窗口偏移**（双重偏移会让框落到两倍远处）
5. **`elements.rs::registry()` 是进程内 OnceLock**——element_index 只在**同一进程**内一致；
   跨进程对账（MCP server vs 测试进程）必然不同号，对账必须同进程双路
6. **ignored 测试的断言也要核对序列化实际值**：serde 的 tag 大小写（`"fail"` vs `"Fail"`）
   想当然写错，Muse 验收时才暴露（52d3576）——写 ignored 测试时先本地打印一次实际输出
7. **D 盘空间**：两盘长期 100%——构建前 `df -h /d`，低于 3G 先清
   `/d/cargo-target/debug/incremental` 与 `examples`（本项目共享 target，可再生）；
   空间耗尽的报错是 `link.exe failed: exit code 1318`，不是代码问题
8. **exe 锁**：3 个常驻 cua-hub.exe（0.1.6 安装目录 + dist）不锁共享 target 的 debug 链接——
   锁冲突只发生在二进制路径重合时；测试构建用共享 target 无碍
9. **门禁三件套**：fmt / clippy `-D warnings` / test --workspace——v0.1.7 发布基线
   **285/0/8**（Muse 实机口径）；本地 283-285 视 ignored 计数
